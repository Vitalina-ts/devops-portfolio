### Завдання 5. Діагностика несправності Docker Compose

Під час виконання завдання було навмисно створено помилку в конфігурації Docker Compose. У файлі `compose.yaml` для сервісу `ui` змінено внутрішній порт із `80` на `81`.

**Неправильне налаштування:**


<img width="877" height="388" alt="image" src="https://github.com/user-attachments/assets/ed8339d4-aaa3-4605-91cf-299cd40af570" />


```yaml
ports:
  - "127.0.0.1:${UI_PORT:-5173}:81"
```

Проблема полягає в тому, що Docker перенаправляє запити на порт `81` усередині контейнера, тоді як вебсервер Nginx прослуховує порт `80`.

Для перевірки стану контейнерів виконано команду:

```powershell
docker compose ps
```

У результаті отримано:

<img width="1506" height="178" alt="image" src="https://github.com/user-attachments/assets/468b9730-8643-42bf-9f96-3a3915d84069" />

```text
wishlist-lab-ui-1
Up (health: starting)
127.0.0.1:5173->81/tcp
```

Після цього перевірено доступність вебзастосунку командою:

```powershell
curl.exe -i http://127.0.0.1:5173
```

**Результат:**

<img width="952" height="82" alt="image" src="https://github.com/user-attachments/assets/45230020-ac26-4a68-b431-92ce838147a8" />

```text
curl: (52) Empty reply from server
```

Це підтвердило, що контейнер запускається, але вебзастосунок недоступний через неправильно налаштоване перенаправлення порту.

Помилку можна виявити на етапі чеклиста **«Перевірка портів і мережевих налаштувань»**, порівнявши вивід `docker compose ps` з конфігурацією Nginx.

Для виправлення необхідно повернути правильний внутрішній порт:

```yaml
ports:
  - "127.0.0.1:${UI_PORT:-5173}:80"
```

**Висновок:** причиною недоступності вебзастосунку є невідповідність внутрішнього порту Docker Compose порту, який прослуховує Nginx. Навіть якщо контейнер успішно запускається, неправильне налаштування портів може зробити сервіс недоступним.
